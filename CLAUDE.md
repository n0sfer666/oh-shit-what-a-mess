# OSWaM — правила проекта

## СТРОГИЕ ПРАВИЛА (НИКОГДА НЕ НАРУШАТЬ!)

### 1. Никогда ничего не удалять вне директории проекта

Агент **НИКОГДА** не удаляет, не перемещает и не перезаписывает файлы за пределами
`/Users/n0sfer/_dev/mac-fkcg-stuck`. Это касается любых инструментов: `rm`, `mv`, `>`,
`truncate`, `git clean`, нативных команд (`docker prune`, `brew cleanup`, `simctl delete`,
`tmutil deletelocalsnapshots`, `log erase`) и любых их эквивалентов.

Запрещено даже «на пробу», «для проверки гипотезы» и «чтобы замерить эффект».
Исключение единственное: явная, конкретная и адресная команда пользователя в текущей сессии
(«удали X»), где X назван прямо. Молчаливое согласие, прошлая аналогичная просьба и
«очевидная польза» разрешением не являются.

Чтение и измерение (`du`, `ls`, `find`, `stat`, `df`, `docker system df`, `simctl list`) —
разрешены везде. Реальную очистку системы делает пользователь сам, запуская `oswam`.

Для временных файлов — только scratchpad-директория сессии, никогда `/tmp` и никогда `~`.

### 2. Нашёл способ освободить место — расширяй oswam без вопросов

Если в ходе любой работы обнаружен новый безопасный способ освободить место на диске
(новый путь-кэш, нативная команда очистки, регенерируемый артефакт) — **сразу**, не
спрашивая разрешения, добавить его в реестр `oswam-core/src/registry/`:

- подобрать правильную категорию (или завести новую, если ни одна не подходит);
- проставить честный `RiskLevel` (см. шкалу ниже);
- предпочитать нативную команду (`NativeCommand`) прямому `rm`, если она существует;
- добавить тест в `oswam-core/src/registry/tests.rs`, пинящий новый таргет;
- о находке сообщить в ответе постфактум, а не до.

Молчать о находке или откладывать «до отдельной задачи» — нарушение правила.

### 3. Заметил дефект безопасности в собственной работе — чини сразу, не спрашивая

Если агент сам обнаружил в своём (или уже существующем) коде проблему из списка ниже — он
**молча чинит её в той же задаче** и сообщает постфактум. Выносить такое пользователю как
вопрос («сделать или нет?», «не блокер, но можно…») — нарушение правила: это перекладывание
инженерного решения, у которого есть единственный правильный ответ.

Чинить без вопросов:

- **неатомарное удаление** — набор путей, составляющих одну сущность, попадает в UI
  раздельно, и частичное удаление оставляет битое состояние (`*.avd` + `*.ini`, образ +
  манифест, БД + WAL);
- **двойной учёт** — таргет является потомком другого таргета либо покрыт `discover`,
  из-за чего байты считаются дважды;
- **нечестный `RiskLevel`** — заниженный (данные пользователя под `Safe`/`Caution`) или
  завышенный «на всякий случай»;
- **обещание ≠ действие** — оценка размера не соответствует тому, что реально удалит команда;
- **молчаливое сокрытие** — цель исчезает из скана из-за неудачной оценки, без объяснения;
- **ложное срабатывание паттерна** — маска задевает исходники, а не артефакты;
- **потеря сигнала риска** — UI называет безопасным то, что заблокировано процессом,
  требует sudo или необратимо.

Правило распространяется и на находки независимого ревью: всё, что `severity ≥ low`,
исправляется в той же задаче без переспрашивания.

### 4. Это opensource-приложение — никаких привязок к текущему пользователю

OSWaM ставит и запускает у себя любой человек. Код, тесты, снапшоты, конфиги и документация
**НИКОГДА** не содержат ничего, что относится только к машине разработчика.

Запрещено:

- **имя пользователя и абсолютный `$HOME`** — ни `/Users/<username>` в продакшн-коде, ни в
  тест-фикстурах, ни в снапшотах. В реестре — только `~/…`, раскрытие через `paths::expand`
  от реального `$HOME`; в тестах — нейтральный `/Users/tester`;
- **личные каталоги и проекты** — конкретные репозитории, рабочие директории, имена машин,
  Apple ID, серийники, пути установленного только у разработчика софта;
- **допущение «у всех так»** — путь из личной конвенции добавляется в реестр только как один
  из нескольких общепринятых вариантов, не вместо них (`~/Developer`, `~/Projects` и т.п.);
- **зависимость от локального окружения** — тест, который проходит только на машине автора
  (существующий каталог, установленный `docker`/`simctl`, конкретный размер диска).
  Внешние утилиты — за `FakeFs`/моком; отсутствие утилиты — штатная ветка, не падение.

Обнаружил такую привязку — чинишь сразу, не спрашивая, и сообщаешь постфактум (см. правило 3).
Личное окружение разработчика живёт в `~/.config/oswam/config.toml`, а не в коде.

### 5. Шкала риска (единственный источник правды — `risk.rs`)

| Уровень   | Смысл                                                              |
|-----------|--------------------------------------------------------------------|
| `Safe`    | кэш/артефакт, регенерируется сам, потеря = только время             |
| `Caution` | регенерируется, но требует перекачки/пересборки или ручного шага    |
| `Danger`  | пользовательские данные; удаление необратимо без переустановки       |
| `Never`   | системное/SIP/root/dataless/защищённое пользователем — не трогать   |

Never-список неизменяем и не расширяется таргетами. Понижать риск таргета ради красивой
цифры в UI запрещено.

### 6. Безопасность реализации

- Деструктивный код тестируется только на `FakeFs`/tmpdir — **никогда** на реальных путях.
- Никаких `sh -c` со склейкой строк в нативных командах: только `Vec<String>` argv.
- Прямое `rm` по `Docker.raw`, `*.qcow2`, `AssetsV2` и прочим контейнерам состояния
  запрещено — только штатная утилита (`docker`, `simctl`, `tmutil`).
- Таргеты, требующие root, помечаются `needs_root` и не появляются в скане без sudo.
- По умолчанию — Корзина; `Permanent` только для `Danger` и явного выбора.

### 7. Код

- Без комментариев в коде (кроме явного запроса пользователя).
- Файлы ≤ 200 строк, одна ответственность — один файл.
- Строгая типизация; без `unwrap()` на горячем пути.
- TDD: тест вперёд. `cargo test`, `cargo clippy --all-targets -- -D warnings`,
  `cargo fmt --check` — зелёные до коммита.
- Коммиты: conventional commits, английский, без AI-подписей, только по явному запросу.

Остальное — `.context/` (архитектура, конвенции, тесты, проверки).
